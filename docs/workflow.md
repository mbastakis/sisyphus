# Using Sisyphus

Capture a Task, make it Ready when you want to tackle it, Start, then Done.
Daily planning is optional.

## The lifecycle

- **Backlog:** worth keeping, not yet committed.
- **Ready:** the small pool you intend to pull from next, with nothing blocking a start.
- **Doing:** started and still in progress. Lunch and overnight pauses need no action.
- **Waiting:** committed work cannot progress until a specific condition clears.
- **Done:** the stated outcome is achieved.

An idea can be actionable and still belong in Backlog. A deadline does not start
or commit work. Shelving unblocked work returns it to Ready; a real blocker puts
it in Waiting. Keep Doing small rather than tracking every momentary pause.

## Today

Today keeps **Doing** prominent and a few **Ready** Tasks within reach. Start
directly from that preview as capacity becomes available, or open the full Ready
pool. **Up next** is an optional shortlist of Tasks deliberately chosen for today.
There is no separate planning step before execution. Complete work when its
outcome is achieved; the completed-today count gives access to finished work.
Press **Cmd+K** (Mac) or **Ctrl+K**, type **Today**, then Enter to use
**Go to Today** in the command palette.

You can also drag Ready Tasks into Up next to choose them, or into Doing to
start. Dragging Doing back to Up next stops execution and keeps the Task chosen
for today; returning it to the Ready pool clears that selection. These moves
never change deadlines. Direct buttons remain available on mobile and keyboard.

Open a Task for details and click outside the side panel to return to the board.
Unsaved edits still ask before being discarded. Relevant actions stay visible
in the panel rather than requiring a More actions menu.
Deferred, Ready, attention, and completed-today panels also close when you click
their dimmed backdrop or press Escape.

Deadline and follow-up attention is distinct from what you chose. Yesterday's
unfinished plans are available to review, not automatically added to today's
commitments. Clearing a daily selection leaves the Task Ready.

## Waiting or later?

“Waiting for the accountant's statement” is a blocker. Record the condition and
optionally a follow-up day. Reaching that day means check, not assume the
statement arrived. Resolving the condition returns work to Ready only if no
other prerequisite remains.

“Revisit backup options next month” is deferral. The Task stays out of the normal
actionable view until its return date, retaining commitment and any blockers.
It does not become today's work automatically. The Deferred count near the top
opens these Tasks with their return dates; Return now brings a Task back early
without starting or selecting it for today.

## Projects

Active projects have committed work. Later holds projects with only backlog or
deferred work. History holds completed-only projects. Search reaches all three;
no project-status upkeep is required. Adding or committing work brings a project
back into the appropriate group without navigating you away from an open board.

## Good Tasks

Use one meaningful, finishable outcome: “Compare three photo-backup options.”
Supporting steps and links belong in annotations. Split work when parts can be
completed or blocked independently, not for every implementation step. Reuse
project names and existing equivalent Tasks. Set real deadlines when there are
real finish-by constraints; no categorization tags are needed.
